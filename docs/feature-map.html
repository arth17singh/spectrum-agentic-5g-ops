Feature map and parallel build plan

Every feature in the SPECTRUM console, where it lives in the code, how the features feed each other, and how a team can build or extend the whole set in parallel through small pull requests without breaking the demo. Part A is the catalogue, Part B shows the relationships, Part C is the build plan. Everything here was checked against the code in frontend/src and backend/spectrum.

How to read this page

Use it in two ways. When you present, use Part A and Part B to answer "where does that number come from?" and "how do the parts connect?". When you build, use Part C to pick a lane, see which files you own, and see which other pull requests you wait for.

  • Feature means one thing you can switch on or off, or one thing a team can own: a screen, a family of panels, an engine capability, or a piece of the console frame.
  • Engine means one Python class in backend/spectrum/engines/. It holds the state of one plane. Most engines run a step ten times a second (the ledger acts only when called).
  • Slice means one part of the browser's data store (frontend/src/core/store.ts). Each engine has exactly one slice with the same name.
  • Flag means an on/off switch defined in core/flags.tsx. A flag is only on if every flag it depends on is also on. See Settings, feature flags and presenter view.

Anatomy of one feature

Every feature in the console is built from the same seven parts. Once you can find these seven parts for one screen, you can find them for all of them. The path of the data is always the same:

  1. EnginePython class, ticks at 10 Hz, emits events with bus.emit
  2. Event busnumbers every event (seq), keeps the last 20,000
  3. WebSocket /wsone socket, batches every 100 ms
  4. Store handlerH['event.type'] in store.ts updates one slice
  5. Panelreads the slice with useLive(s => s.slice) and re-renders

Commands go the other way. A button calls a function in core/api.ts, which sends POST /api/… to backend/spectrum/main.py. The route calls one engine method. The engine changes its state, emits events, and often appends a signed record to the ledger. The browser never changes a slice directly from a button press, with one exception listed under known gaps.

How a page gets its first data

On connect, core/ws.ts opens the WebSocket, holds incoming events in a buffer, fetches GET /api/snapshot (all ten slices plus the last 400 stream events), loads it with loadSnapshot, then replays only the buffered events with a higher seq. That is why a freshly opened tab is complete at once and never double-counts. A system.reset event triggers the same resync.

A3. Backend engine capabilities

Nine engines plus the provenance builder. The AWS target column is copied from each file's header comment. Engine.build in engine.py creates them in a fixed order and passes each one the shared clock and bus, plus the key ring, ledger and other engines where needed. Engine.tick then calls them in this order every 100 ms: scheduler, federation, proving, release, twin, swarm, trust, oversight, observability.

The orchestrator itself is a feature too. C1. Principles

  1. Contracts first. Wave 0 merges the shapes everyone shares: the event envelope, the snapshot keys, the slices, the complete api object, the manifest, the flags, the design tokens and the engine and adapter interfaces. After that, lanes rarely need to talk.
  2. One lane, one engine and its screen. A lane owns a vertical slice: engines/x.py, its routes, its events, its slice handlers and features/x/. Most pull requests then touch only files the lane owns.
  3. Shared files are append-only. Registries (features/index.ts, FLAGS, the api object, the handler map, NOISY, PULSE) only gain lines. Nobody reorders or reformats them.
  4. New things start off. A new flag ships with default: false until its screen is reviewed in both themes, so a half-built feature cannot appear during a demo. A pull request that registers a manifest or adds a <Gate flag=…> must add the FLAGS entry in the same pull request: an id missing from FLAGS resolves to on (rawValue falls back to ?? true).
  5. The 14 beats are the integration test. test_full_demo_script_runs_end_to_end in backend/tests/test_engine.py runs every beat. From wave 4 on (CP4), it must stay green on every merge. Before that, each lane gates on its own per-engine tests.

C12. Recipe: adding a new feature

The Settings page's "Adding or removing a screen" panel gives the frontend half. Here is the full path, front and back, as two stacked pull requests in one lane.

  1. Engine. Add backend/spectrum/engines/<x>.py with __init__(clock, bus, …), tick(dt) and snapshot(). Emit events with bus.emit; append to the ledger for anything a judge might ask to prove.
  2. Wire it. One line in Engine.build, one call in Engine.tick, one key in Engine.snapshot. Reviewed by the integration lead.
  3. Routes. Add async def handlers in main.py (or the lane's router) that call engine methods and return ok(…). Mind route order: a new fixed path under an existing {action} route must be declared before it.
  4. Test. Add tests/test_<x>.py with a behavioural test (on the per-engine fixtures once W0-4 lands). Run make test.
  5. Slice. Add the slice key to SliceKey, LiveState, the initial value in useLive = create(…), the Snapshot interface in core/types.ts and loadSnapshot; add handlers to H (or the lane's slice file). Add chatty event types to NOISY, which is append-only for the lane that owns the event.
  6. Client. Add one function per endpoint to api.ts.
  7. Screen. Create features/<x>/manifest.ts and its page; add one line to features/index.ts; in the same pull request add screen.<x> to FLAGS with default: false (an id missing from FLAGS would resolve to on). Route, rail entry, palette entry and g letter appear by themselves.
  8. Turn it on. After review in both themes, set the default to true. If it belongs in the demo, append a beat at the end of BEATS in a separate pull request (never renumber), update the 14 in main.py director_beat and range(1, 15) in the full-script test, and update this guide. Beats above 9 are reachable only with the arrow keys, the palette or the Director.
